# Project Vision

## The idea

Project Nexus is a personal digital command center: one approachable place to connect plans, projects, learning, and creative work. It should make it easier to answer three everyday questions:

1. What matters to me right now?
2. What is the next small action I can take?
3. Where should I capture the result or idea so I can find it again?

The project begins as a set of useful documents, not a complicated application. Its structure and tools can evolve as real needs become clear.

## Who it is for

Project Nexus is designed for an individual who wants more clarity and momentum without needing a technical background, expensive subscriptions, or a desktop computer. The workflows should be understandable and maintainable from an iPhone.

## What success looks like

- Important projects and ideas have a clear, easy-to-find home.
- Each active project has a manageable next action.
- Creative work can move from idea to completion through a repeatable process.
- Notes and plans are simple enough to maintain consistently.
- The system remains useful with free tools and does not depend on paid hosting.
- Private credentials stay private and are never committed to the repository.

## Guiding principles

### Start small
Build the simplest useful version first. Documentation and a manual routine are valid product features. Add automation or code only when a repeated pain point justifies it.

### Free-first and portable
Prefer free plans, open formats such as Markdown, and tools that make it easy to keep or move your own information. Do not make a credit card, paid service, or paid hosting a prerequisite.

### Friendly to beginners and phones
Use plain language, short steps, and familiar interfaces. Keep routine planning and updates possible with the GitHub app or a mobile browser on iPhone. Avoid workflows that require command-line access or a laptop as the default.

### Protect privacy
Keep passwords, API keys, tokens, recovery codes, and personal information out of public files, commits, issues, and screenshots. Use a provider’s secure credential manager only if a future feature truly needs credentials, and document safe handling without publishing the values.

### Keep the human in control
The system should support decisions rather than create busywork. Plans are suggestions; the owner chooses priorities and can change the workflow at any time.

## What Project Nexus is not (yet)

- It is not a custom app that needs to be built before it can help.
- It does not require paid hosting, a paid AI service, or a credit card.
- It is not intended to automate every decision or add complexity for its own sake.

## A practical first milestone

Use the README, roadmap, and a real creative workflow for a short period. Notice what is hard to find, what is repeated, and what is not useful. Improve the documents first; consider software only after a specific need is clear.
